Тема заняття

Застосування принципів графічного дизайну для візуалізації даних в інформаційно-аналітичних системах.

Навчальні питання: 1. Принципи графічного дизайну. 2. Застосування принципів графічного дизайну для візуалізації даних.

Навчальна мета

Навчитися організовувати дані на інформаційних панелях так, щоб аналітик міг швидко побачити головне, правильно інтерпретувати показники та виявляти відхилення.

Очікувані результати

Слухач пояснює шість принципів дизайну, розрізняє якісне та невдале оформлення, обирає тип графіка, створює та презентує простий прототип дашборду.

Питання для обговорення: якщо ІАС містить достовірні дані, але аналітик не може за 10 секунд знайти критично важливий показник, наскільки ефективним є її інтерфейс?

Принципи графічного дизайну

Графічний дизайн — цілеспрямована організація тексту, кольору, форми, простору та графіки для передавання інформації. В ІАС він служить точності та швидкості сприйняття, а не лише естетиці.

Композиція

Логічне розташування блоків: від загального зведення до деталей. Приклад: заголовок → KPI → динаміка → таблиця.

Баланс

Рівновага візуальної ваги. Великий головний графік поруч із кількома компактними показниками може бути збалансованим.

Контраст

Виділення відмінностями в розмірі, кольорі чи насиченості. Прострочені донесення потребують помітного, але не кричущого акценту.

Ієрархія

Найважливіше користувач бачить першим: стан, ключове число, тренд, деталізація, джерело.

Колір

Обмежена палітра та постійна семантика: синій — нейтральні показники, помаранчевий — увага. Колір дублюється текстом.

Типографіка й простір

Читабельні шрифти, заголовки, числові значення, відступи та whitespace. Не перевантажуйте екран.

Демонстрація кейсів та візуалізацій

Навчальний аналітичний дашборд

Виберіть напрям та період. Дані синтетичні й ілюстративні.

Розподіл за категоріями

Динаміка за період

Порівнюємо значення на спільній шкалі; підписуємо часовий період.

Дашборд або інфографіка?

Дашборд — екран для моніторингу та аналізу змінних показників. Інфографіка — пояснювальна візуальна історія. Для порівняння категорій частіше використовують стовпчики, для тенденції — лінію, для частин цілого — складену смугу або, за малих категорій, кругову діаграму.

Адаптивність і точність

Показники мають залишатися зрозумілими на великому екрані та ноутбуці. Позначайте одиниці вимірювання, дату, джерело, підписуйте категорії. Не змінюйте масштаб для штучного посилення відмінностей.

Зв’язок frontend, backend та API

HTML створює структуру та місце для графіків; CSS задає палітру, типографіку та відступи; JavaScript отримує й оновлює дані; Flask API обробляє HTTP-запити та повертає JSON; PostgreSQL може зберігати реальні записи.

fetch('/api/stats') .then(response => response.json()) .then(data => console.log(data));

На цій публічній навчальній сторінці демонстраційні графіки працюють у браузері без сервера й бази даних. Наведений вище код є прикладом для окремого локального Flask-проєкту.

Створення прототипу у VS Code

Завдання для команд

Створіть простий дашборд на синтетичних даних. Група 1 — донесення; група 2 — технічне обслуговування; група 3 — навчання персоналу; група 4 — логістичні заявки. Покажіть мінімум три показники й один графік, поясніть композицію, баланс, контраст, ієрархію, палітру, типографіку та whitespace.

Використовуйте лише вигадані дані, умовні назви та безпечні приклади; не публікуйте реальні відомості про військові підрозділи, людей чи ресурси.

Покрокове виконання

1
Створіть у VS Code папку dashboard-57, у ній файли index.html, static/style.css та static/app.js. Команда mkdir static створює каталог для стилів і скриптів.
2
У HTML створіть заголовок, три інформаційні картки, контейнер графіка та підключіть CSS/JS.
<!doctype html> <html lang="uk"> <head> <meta charset="utf-8"> <link rel="stylesheet" href="static/style.css"> </head> <body> <h1>Моніторинг донесень</h1> <main class="dashboard"> <article class="card">Усього: <strong id="total">—</strong></article> <article class="card">Виконано: <strong id="done">—</strong></article> <article class="card">Прострочено: <strong id="late">—</strong></article> </main> <script src="static/app.js"></script> </body></html>

Тег <link> підключає CSS, <script> підключає JavaScript, а атрибут id дозволяє знайти елемент для оновлення.

3
Додайте оформлення у static/style.css.
body {font-family:Arial,sans-serif;background:#f3f7f8;color:#173a49;padding:24px} .dashboard {display:grid;grid-template-columns:repeat(auto-fit,minmax(180px,1fr));gap:16px} .card {background:white;padding:24px;border-radius:12px;border:1px solid #d7e4e7} strong {display:block;font-size:32px;color:#206b87}

display:grid створює сітку; gap — відступи; background — фон; font-size задає візуальну ієрархію.

4
Заповніть дані в static/app.js.
const data = {total:100,done:84,late:5}; document.getElementById('total').textContent = data.total; document.getElementById('done').textContent = data.done; document.getElementById('late').textContent = data.late;

const створює змінну, getElementById знаходить HTML-елемент, textContent змінює напис на сторінці.

5
Відкрийте index.html у браузері, перевірте відображення та вдоскональте дизайн. Для окремого Flask API використайте app.py, templates і static (приклад архітектури наведено на вкладці кейсів).

Типові помилки

Не застосовується CSS: перевірте href та ім'я файлу. Не оновлюються показники: перевірте src JavaScript і правильність id. Порожній графік: перевірте дані та консоль браузера (F12). Помилка 404 API: переконайтеся, що Flask запущено й маршрут існує. Занадто строкато: залиште 2–3 основні кольори та один акцент.

Підсумки заняття

Що потрібно запам’ятати?

Візуалізація має допомагати аналізу: спочатку користувач бачить важливі показники, потім динаміку й деталі. Графічний дизайн — не декор, а спосіб забезпечити правильне сприйняття. Frontend представляє дані, backend отримує й обробляє їх, API поєднує обидві частини.

2. Який графік найкраще показує динаміку за днями?

3. Що повертає Flask API клієнтському JavaScript?
